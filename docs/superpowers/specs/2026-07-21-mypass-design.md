# MyPass — менеджер паролей: дизайн

Дата: 2026-07-21
Статус: утверждён

## Цель и контекст

Личный менеджер паролей для macOS (MVP), затем iOS/iPadOS. Автозаполнение через
расширения Chrome и Safari. Синхронизация базы через iCloud Drive, локальную
папку или SFTP. Публикация в App Store не планируется — установка через Xcode.

## Ключевые решения

| Решение | Выбор |
|---|---|
| Стек | Swift + SwiftUI, единая кодовая база macOS/iOS |
| Формат базы | KeePass KDBX4 (Argon2id; совместимость с KeePassXC/Strongbox) |
| Архитектура | Единое приложение — центр; расширения — тонкие клиенты (вариант A) |
| MVP | macOS-приложение + 3 бэкенда синхронизации + расширения Chrome/Safari + TOTP |
| Passkeys | Отдельная фаза после iOS; формат хранения (конвенция KeePassXC) закладывается сразу |
| SSH-аутентификация | Ключи и OpenSSH-сертификаты (`*-cert.pub`) |

## Архитектура и компоненты

```
mypass/
├── Packages/
│   ├── MyPassKit/        # Ядро: kdbx4, крипто, модель, TOTP, генератор паролей
│   └── SyncKit/          # Протокол StorageBackend + 3 реализации + merge
├── MyPass/               # macOS-приложение (SwiftUI): окно + меню-бар
├── SafariExtension/      # Safari Web Extension (встроена в приложение)
├── ChromeHost/           # Native Messaging host для Chrome
└── WebExtension/         # Общий JS-код расширений (Chrome и Safari)
```

- **MyPassKit** — единственное место с расшифрованными данными. Чтение/запись
  KDBX4, модель Group/Entry, TOTP (RFC 6238), генератор паролей. Без
  зависимостей от UI и сети. Библиотека kdbx: первый кандидат — KeePassKit
  (ObjC); если поддержка KDBX4 неудовлетворительна — собственный парсер
  (CryptoKit + C-библиотека Argon2). Решение фиксируется в начале фазы 1.
- **SyncKit** — протокол `StorageBackend` (read / write / modificationDate /
  exists) и реализации: локальная папка, iCloud Drive, SFTP. Merge-движок общий.
- **Приложение** — владеет разблокированной базой, UI, отвечает расширениям по IPC.
- **Расширения** — определяют формы, запрашивают `getCredentials(url)`,
  заполняют. Базы и ключей не имеют. Safari → нативный handler; Chrome →
  Native Messaging host → XPC → приложение.

Поток автозаполнения: content script находит форму → запрос по URL → приложение
возвращает совпадения по домену → пользователь выбирает → заполнение.

## Модель безопасности

- Мастер-пароль → Argon2id → ключ базы. Расшифрованные данные только в памяти
  процесса приложения.
- **Touch ID:** производный ключ (не мастер-пароль) в Keychain с
  `kSecAccessControlBiometryCurrentSet`; инвалидация при смене отпечатков;
  мастер-пароль обязателен после перезагрузки.
- **Автоблокировка:** таймаут бездействия (по умолчанию 15 мин), сон,
  ручная команда; опционально — при блокировке экрана. Ключи затираются.
- **Расширения:** получают только записи, подходящие под URL активной вкладки,
  по явному запросу. Сопоставление по домену делает приложение. XPC принимает
  соединения только от процессов с ожидаемой подписью кода. Chrome-host
  привязан манифестом к ID расширения. База заблокирована → статус «locked»,
  разблокировка только в приложении.
- **Заполнение:** только по действию пользователя; сверка origin страницы с URL
  записи; без автозаполнения при загрузке.
- **Файл базы:** атомарная запись (temp → rename); перед каждой перезаписью —
  резервная копия (ротация, по умолчанию 10).

## Синхронизация

Приложение работает с **локальной рабочей копией** (Application Support);
бэкенд — удалённая точка правды. Полный офлайн для всех режимов.

Цикл (при открытии, после сохранения, по таймеру, вручную):
1. Скачать удалённый файл, если изменился.
2. Не менялся → загрузить свой.
3. Менялся → merge на уровне записей → загрузить результат.
4. Загрузка атомарна (для SFTP: upload во временное имя → rename на сервере).

**Merge** (семантика KeePassXC Synchronize):
- Сопоставление по UUID записи/группы.
- Конкурентные правки → побеждает более новый `lastModificationTime`,
  проигравшая версия сохраняется в History записи.
- Удаления через `DeletedObjects`: удаление против правки — по времени события.
- Перемещения — по `locationChanged`.
- Диалогов выбора версии нет; конфликты разрешаются автоматически и обратимо.

**Бэкенды:**
- *iCloud Drive:* NSFileCoordinator + NSFilePresenter; conflict-версии
  (NSFileVersion) прогоняются через merge и удаляются.
- *Локальная папка:* выбор папки пользователем, security-scoped bookmark,
  FSEvents для внешних изменений.
- *SFTP:* host, port, путь, пользователь, приватный ключ (файл или ~/.ssh),
  опционально OpenSSH-сертификат. Host key — TOFU по known_hosts.
  Passphrase ключа — в Keychain. Кандидаты библиотек: Citadel, mft (libssh).

Сбой сети посреди sync → рабочая копия не тронута, повтор в следующем цикле.

## UI и функциональность MVP

Трёхколоночное окно (`NavigationSplitView`): группы → записи → детали.

- Записи: название, логин, пароль, URL, заметка, TOTP, произвольные поля.
  Копирование с автоочисткой буфера через 30 сек.
- Группы: дерево, drag-and-drop, корзина (Recycle Bin) с восстановлением.
- TOTP: ввод `otpauth://` или secret; живой код с таймером.
- Поиск: мгновенный, по всем полям, глобальный.
- Генератор паролей: длина, классы символов; в редакторе и в меню-баре.
- История записи: просмотр и восстановление версий.
- Меню-бар: статус, быстрый поиск, блокировка, генератор. Закрытие окна не
  завершает приложение.
- Импорт: CSV; открытие существующих .kdbx.
- Настройки: бэкенд, таймаут блокировки, Touch ID, число резервных копий.

Расширения: счётчик совпадений на иконке, список → выбор → заполнение; кнопка в
поле пароля; генерация пароля; предложение сохранить новый логин (подтверждение
в приложении).

## Тестирование

- **MyPassKit:** round-trip тесты; кросс-совместимость с эталонными файлами
  KeePassXC (разные KDF/шифры/структуры) в обе стороны — главная страховка от
  порчи данных.
- **Merge:** табличные тесты всех сценариев (добавление/правка/удаление/
  перемещение с обеих сторон).
- **SyncKit:** SFTP против локального sshd в Docker (ключи, сертификаты, обрыв
  посреди записи); файловые бэкенды — временные папки.
- **Расширения:** JS-тесты определения форм на сохранённых страницах реальных
  сайтов; сквозной сценарий — вручную по чек-листу.
- **UI:** точечно.

## Фазы

1. **Ядро** — MyPassKit; решение KeePassKit vs свой парсер.
2. **Приложение (локально)** — полный UI, локальный файл, Touch ID,
   автоблокировка, меню-бар. Уже пригодно к использованию.
3. **Синхронизация** — папка → iCloud → SFTP; общий merge.
4. **Расширения** — общий JS, Safari-таргет, Chrome-хост, IPC.

Вне MVP: 5 — iOS/iPadOS + AutoFill; 6 — passkeys.

## Риски

| Риск | Митигация |
|---|---|
| KeePassKit слаба на KDBX4 | Проверка на эталонных файлах в первые дни фазы 1; запасной план — свой парсер |
| SFTP-библиотека без OpenSSH-сертификатов | Ранний прототип в фазе 3; худший случай — C-биндинги libssh |
| iCloud задерживает выгрузку | NSFileCoordinator + проверка перед merge; merge переживает устаревшую копию |
| Порча базы багом записи | Кросс-тесты с KeePassXC + резервные копии перед каждой записью |
