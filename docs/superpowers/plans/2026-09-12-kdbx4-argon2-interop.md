# KDBX4 Argon2 Interoperability — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make MyPass open real KeePass/KeePassXC KDBX4 vaults, and keep vaults MyPass writes openable by them, by replacing `Packages/MyPassKit`'s Argon2 backend. Today `KeyDerivation.argon2id` calls swift-sodium's `crypto_pwhash`, which hardcodes a 16-byte Argon2 salt; every real-world KDBX4 file uses 32 bytes, so any vault ever touched by KeePass 2.x or KeePassXC currently fails to open with `unsupportedFeature("KDF: sodiumFailure")`. Two more constraints compound the gap: parallelism is rejected unless it's exactly 1, and Argon2d (the historical KeePass default before KeePassXC switched to Argon2id) has no dispatch branch at all.

**Architecture:** Vendor the reference `phc-winner-argon2` C implementation as a new SwiftPM C target, `CArgon2`, inside `Packages/MyPassKit`. `KeyDerivation.swift` calls into it directly (`argon2_hash`) instead of swift-sodium's `Sodium().pwHash.hash`, for both Argon2id and a new Argon2d branch. swift-sodium is **not** removed — it keeps backing the outer ChaCha20 stream cipher and the inner random stream cipher, which are unrelated to Argon2. `KdbxDatabase.save` starts writing a 32-byte salt and parallelism 2 (still Argon2id, still 64 MiB / 3 iterations). Every constraint lifted gets its own known-answer vector, computed independently via Python's `argon2-cffi` — never by this codebase's own (possibly wrong) implementation.

**Tech Stack:** Swift 5.10 (SwiftPM C target interop), C (vendored `phc-winner-argon2`, portable reference/`ref` variant only — the target platform is arm64, and the SSE-optimized `opt` variant uses x86 intrinsics that won't compile there), XCTest, Python 3 + `argon2-cffi` (independent known-answer vectors) + `pykeepass` (fixture regeneration and the out-of-process bidirectional proof).

**Spec:** `docs/superpowers/specs/2026-09-12-kdbx4-argon2-interop-design.md`

## Why this task order

Task 2 swaps the Argon2 backend from swift-sodium to the vendored library while changing **no observable behavior** for the one input shape both backends already handle correctly (16-byte salt, parallelism 1) — proven by `KeyDerivationTests.testTransformedKeyMatchesIndependentArgon2idKnownAnswer`, a test that already exists, already passes, and is required to keep passing **completely unmodified**. That ordering exists so the backend swap itself is never in question by the time the real fix work starts: only after Task 2 is confirmed behavior-preserving does Task 3 lift the salt-length constraint, Task 4 lift the parallelism constraint, and Task 5 add the missing Argon2d branch — one constraint at a time, each pinned by its own independently-generated known-answer vector, so a regression in any one of them is attributable to exactly one task's diff.

**A finding from building this plan, worth stating up front so Task 2 isn't a surprise:** swapping the backend in Task 2 does not merely preserve old behavior — it also unlocks *more* than intended at that point, because the vendored library has no compiled-in salt-length limit at all (unlike swift-sodium, which enforced 16 bytes in the C ABI itself). Verified directly against this repository's actual fixtures (`Packages/MyPassKit/Tests/MyPassKitTests/Fixtures/argon2id-aes256-gzip.kdbx`, 32-byte salt, `P=1`): the moment Task 2's swap lands, that fixture already opens successfully, one task before Task 3's explicit salt-length guard even exists and three tasks before Task 6 is supposed to flip the tests that currently assert failure. Task 2 accounts for this explicitly (see its Step 5) rather than leaving the suite red between Task 2 and Task 6.

Tasks 6 through 10 then move from "the derivation is correct" to "the whole system is correct": realistic fixtures and an Argon2d fixture (6), the write path catching up to what real files look like (7), an out-of-process proof that the bidirectional claim isn't just inference from matching known-answer vectors (8), a truthful error surface and UI (9), and build/performance/documentation closure (10).

## Task 1 — Vendor phc-winner-argon2 as a C target

Vendors the reference Argon2 implementation and proves it computes correctly, in complete isolation from any MyPass code. Nothing in `KeyDerivation.swift` changes in this task.

**Interfaces:**
- Produces: SwiftPM target `CArgon2` (module `CArgon2`, public header `argon2.h`); C entry points `argon2_hash`, `argon2id_hash_raw`, `argon2_error_message` become callable from Swift via `import CArgon2`; Swift-bridged types `Argon2_type` (cases `Argon2_d`, `Argon2_i`, `Argon2_id`) and `Argon2_ErrorCodes` (cases `ARGON2_OK`, `ARGON2_SALT_TOO_SHORT`, etc., each with `.rawValue: Int32`).
- Consumes: nothing in this codebase yet.

**A build-integration trap, discovered and fixed while writing this plan — read before Step 5:** `Packages/MyPassKit` already depends on swift-sodium, and libsodium ships its own copy of `blake2b` (`libsodium_la-blake2b-ref.o`) with ordinary external linkage. The Argon2 reference implementation also compiles its own `blake2b.c` with external linkage. Link both into the same test binary unmodified and you get:

```
duplicate symbol '_blake2b' in:
    .../CArgon2.build/blake2/blake2b.c.o
    .../libsodium.a[arm64][29](libsodium_la-blake2b-ref.o)
duplicate symbol '_blake2b_init' in: ...
duplicate symbol '_blake2b_init_key' in: ...
duplicate symbol '_blake2b_init_param' in: ...
duplicate symbol '_blake2b_update' in: ...
duplicate symbol '_blake2b_final' in: ...
ld: 6 duplicate symbols
```

This is reproducible today, verified directly against this repo's actual dependency graph. Marking the symbols `hidden` (e.g. defining `A2_VISCTL`, which `argon2.h` maps to `__attribute__((visibility("hidden")))` on `ARGON2_LOCAL`) does **not** fix it — hidden visibility suppresses a symbol's *dynamic* export, not its presence in a static archive's global symbol table, so the linker still sees two definitions of `_blake2b` and still refuses (verified: the duplicate-symbol error above was reproduced *with* `A2_VISCTL` defined). The actual fix is to rename the seven `blake2b*` symbols this target's `blake2b.c` defines, via object-like preprocessor macros passed as C compiler flags — applied consistently to every file in the `CArgon2` target so `core.c`'s internal calls to `blake2b_long` etc. get renamed identically. This is why the target's `cSettings` in Step 5 below list all seven names explicitly; the "one place" caution that later applies to the M-bytes-to-KiB conversion (Task 2) does not apply here — the renaming is inherently seven separate identifiers.

```swift
import XCTest
import CArgon2

/// Sanity check that the vendored C target builds and computes Argon2id
/// correctly, calling the C entry point directly — before any MyPass Swift
/// code (`KeyDerivation`, Task 2) depends on this library at all.
///
/// Uses the exact same independently-generated known-answer vector as
/// `KeyDerivationTests.testTransformedKeyMatchesIndependentArgon2idKnownAnswer`
/// (see that test's doc comment for the full `argon2-cffi` provenance:
/// secret "correct horse battery staple", salt `0x00..0x0F`, time_cost=2,
/// memory_cost=19*1024 KiB, parallelism=1, type=ID, version=19) — a vector
/// generated with a *different* Argon2id implementation (Python's
/// `argon2-cffi`, itself wrapping this same phc-winner-argon2 reference
/// code) than the one this test calls. An identical result here means the
/// vendored C sources were copied and built without alteration, and gives
/// Task 2 a foundation it can build on: this test proves the library is
/// right, Task 2's untouched test proves the Swift wrapper doesn't break it.
final class CArgon2VendoringTests: XCTestCase {
    func testArgon2idHashRawMatchesIndependentKnownAnswer() {
        let password = Array("correct horse battery staple".utf8)
        let salt = Array((0..<16).map { UInt8($0) })
        var hash = [UInt8](repeating: 0, count: 32)

        let result = password.withUnsafeBufferPointer { pwdPtr in
            salt.withUnsafeBufferPointer { saltPtr in
                hash.withUnsafeMutableBufferPointer { hashPtr in
                    argon2id_hash_raw(
                        2, UInt32(19 * 1024), 1,
                        pwdPtr.baseAddress, pwdPtr.count,
                        saltPtr.baseAddress, saltPtr.count,
                        hashPtr.baseAddress, hashPtr.count
                    )
                }
            }
        }

        XCTAssertEqual(result, ARGON2_OK.rawValue)
        let expected: [UInt8] = [
            0x81, 0x82, 0x59, 0xb6, 0x31, 0x00, 0x26, 0xa8,
            0xe0, 0xdb, 0xac, 0x5d, 0x2e, 0x69, 0x27, 0xab,
            0xcf, 0xdb, 0x07, 0xb3, 0x22, 0x58, 0xfa, 0xc4,
            0xf6, 0x1b, 0x18, 0xb8, 0x0f, 0x92, 0x90, 0x85,
        ]
        XCTAssertEqual(hash, expected)
    }
}
```

```swift
// Replace this block:
        let sodium = Sodium()
        guard let derived = sodium.pwHash.hash(
            outputLength: 32,
            passwd: [UInt8](compositeKey),
            salt: [UInt8](salt),
            opsLimit: Int(iterations),
            memLimit: Int(memoryBytes),
            alg: .Argon2ID13
        ) else {
            throw KeyDerivationError.sodiumFailure
        }
        return Data(derived)

// With:
        // KDBX gives `M` in bytes; the vendored Argon2 reference library's
        // `m_cost` parameter is in KIBIBYTES (1024-byte units) — see
        // phc-winner-argon2's `include/argon2.h`, `Argon2_Context.m_cost`'s
        // doc comment ("amount of memory requested (KB)"), and
        // `argon2_hash`'s own doc comment. This conversion happens in
        // exactly ONE place in this codebase — do not duplicate it
        // elsewhere (Task 5 shares this same call site for Argon2d rather
        // than copying the conversion into a second function).
        //
        // Getting it wrong does not throw or crash: `argon2_hash` accepts
        // any `m_cost` in its valid range and derives A key, just not the
        // RIGHT key. An off-by-1024 error here silently derives a key
        // that is, from the outside, bit-for-bit indistinguishable from
        // what a wrong master password would produce — the vault just
        // fails to open, with nothing pointing at this line. The only
        // thing that can catch a self-consistent-but-wrong conversion
        // factor is a known-answer vector computed by a wholly
        // independent Argon2id implementation — see
        // `testTransformedKeyMatchesIndependentArgon2idKnownAnswer`,
        // which pins exactly this path with M = 19 * 1024 * 1024 bytes.
        let memoryKibibytes = UInt32(memoryBytes / 1024)

        var hash = [UInt8](repeating: 0, count: 32)
        let compositeKeyBytes = [UInt8](compositeKey)
        let saltBytes = [UInt8](salt)
        let result = compositeKeyBytes.withUnsafeBufferPointer { pwdPtr in
            saltBytes.withUnsafeBufferPointer { saltPtr in
                hash.withUnsafeMutableBufferPointer { hashPtr in
                    argon2_hash(
                        UInt32(iterations), memoryKibibytes, parallelism,
                        pwdPtr.baseAddress, pwdPtr.count,
                        saltPtr.baseAddress, saltPtr.count,
                        hashPtr.baseAddress, hashPtr.count,
                        nil, 0,
                        Argon2_id, UInt32(ARGON2_VERSION_13.rawValue)
                    )
                }
            }
        }
        guard result == ARGON2_OK.rawValue else {
            throw KeyDerivationError.sodiumFailure
        }
        return Data(hash)
```

Also update the doc comment above `argon2id` (currently titled "Argon2id key derivation via swift-sodium's `crypto_pwhash` binding" and describing swift-sodium-specific details that are no longer true, like the hardcoded 16-byte salt and "libsodium's public API does not expose a parallelism parameter"): replace it with a comment describing the VariantDictionary keys (still accurate) and noting the parallelism/salt-length guards are about to be relaxed in Tasks 3–4, not because this backend can't do better, but one constraint at a time.

```swift
    /// and passing it here by mistake would not fail, it would silently
    /// derive a different, wrong key. See
    /// `testTransformedKeyMatchesIndependentArgon2dKnownAnswer` for the
    /// test that exists specifically to catch a mixed-up `type` argument
    /// at this call site.
    private static func argon2Derive(type: Argon2_type, compositeKey: Data, params: VariantDictionary) throws -> Data {
        guard case .byteArray(let salt)? = params.items["S"],
              case .uint64(let memoryBytes)? = params.items["M"],
              case .uint64(let iterations)? = params.items["I"],
              case .uint32(let parallelism)? = params.items["P"],
              case .uint32(let version)? = params.items["V"] else {
            throw KeyDerivationError.invalidParameters
        }

        // see Task 3).
        guard salt.count >= 8 else {
            throw KeyDerivationError.invalidParameters

        // into Swift — see Task 4).

            throw KeyDerivationError.invalidParameters
        }
        guard version == 0x13 else {
            throw KeyDerivationError.invalidParameters
        }

        // KIBIBYTES. Exactly one conversion site — see Task 2's writeup
        // on this same line for the full "getting it wrong doesn't
        // throw" rationale.
        let memoryKibibytes = UInt32(memoryBytes / 1024)

        let compositeKeyBytes = [UInt8](compositeKey)
        let saltBytes = [UInt8](salt)
        let result = compositeKeyBytes.withUnsafeBufferPointer { pwdPtr in
            saltBytes.withUnsafeBufferPointer { saltPtr in
                hash.withUnsafeMutableBufferPointer { hashPtr in
                    argon2_hash(
                        UInt32(iterations), memoryKibibytes, parallelism,
                        pwdPtr.baseAddress, pwdPtr.count,
                        saltPtr.baseAddress, saltPtr.count,
                        hashPtr.baseAddress, hashPtr.count,
                        nil, 0,
                        type, UInt32(ARGON2_VERSION_13.rawValue)
```
